Greedy Algorithm Deep-Dive

Understanding the mathematical and structural logic behind job scheduling with deadlines

The Job Sequencing with Deadlines problem is a classic optimization problem. Given a set of $N$ jobs, where each job has a specified deadline $D_i$ (where $D_i \ge 1$) and a associated profit $P_i$. Each job takes exactly $1$ unit of time to complete, and only one job can be run on the system at any given point in time. A job yields its profit only if it is completed before or at its deadline.

Our goal is to schedule the jobs in a way that maximizes the total profit.

The Scheduling Constraint

If a job has a deadline of $d$, it means it must start at or after time $0$ and finish by time $d$. Since each job takes $1$ unit of time, the job must be scheduled in one of the time intervals $[0, 1], [1, 2], \dots, [d-1, d]$. If all of these intervals are already occupied by other jobs, this job cannot be scheduled and must be rejected.

To solve this problem efficiently, we apply the Greedy Strategy. The greedy approach makes the locally optimal choice at each stage with the hope of finding a globally optimal solution.

Step-by-Step Greedy Process:

  1. Sort: Sort all the jobs in descending order of their profit. This ensures we prioritize higher profit tasks first.
  2. Find Max Deadline: Identify the maximum deadline among all jobs. This tells us the maximum time slots available (e.g., if the maximum deadline is $T$, we have slots from $0$ up to $T$).
  3. Initialize Timeline: Initialize all $T$ slots as empty/free.
  4. Iterative Assignment: For each job in the sorted list:
    • Look for a free slot. We start scanning from the latest possible slot for this job (which is $\text{min}(\text{maxDeadline}, \text{jobDeadline})$) and move backward towards slot 1.
    • If a free slot is found (say slot $t$, representing interval $[t-1, t]$), assign the job to this slot, mark the slot as occupied, and add the job's profit to our running total.
    • If all slots from the job's deadline down to 1 are already filled, the job is skipped and rejected.

Why do we scan backward? Because by placing a job in the latest possible slot closer to its deadline, we leave the earlier slots free for jobs with tighter deadlines.

// Greedy Job Sequencing with Deadlines
function JobSequencing(jobs[], n) {
// 1. Sort jobs by profit in descending order
sort(jobs, jobs + n, compareByProfitDescending)
// 2. Find maximum deadline to define timeline size
max_deadline = 0
for i = 0 to n - 1:
max_deadline = max(max_deadline, jobs[i].deadline)
// 3. Initialize slots array with empty value
slots = array[max_deadline + 1] filled with null
total_profit = 0
scheduled_jobs_count = 0
// 4. Iterate over sorted jobs and fit them in latest available slots
for i = 0 to n - 1:
for j = min(max_deadline, jobs[i].deadline) down to 1:
if slots[j] is null:
slots[j] = jobs[i].id // Assign job to slot
total_profit += jobs[i].profit
scheduled_jobs_count++
break // Job assigned, move to next job
return total_profit, slots
}

Analyzing the algorithmic complexity of the standard Greedy approach:

Time Complexity O(N²)

In the worst case, for each of the $N$ jobs, we search up to $D$ slots backwards. Sorting takes $O(N \log N)$, but slot search takes $O(N \times D)$ which reduces to $O(N^2)$ if deadlines are proportional to $N$.

Space Complexity O(D)

We require an array of size $D$ (maximum deadline) to represent the available slots in the execution timeline.

Optimization Note (Disjoint Sets)

The time complexity can be optimized to $O(N \log N)$ using a Disjoint Set Union (DSU) data structure to find the next available free slot in $O(\alpha(D))$ time instead of iterating backward sequentially. This is a common extension studied in advanced design of algorithms.
